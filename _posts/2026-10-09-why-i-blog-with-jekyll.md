写博客这件事，我想要的只有两点：写的时候不被打断，写完之后不用维护。

## 一个博客需要什么

拆开看其实就三件事：

1. 文章有一个固定的地方放，最好是普通的文本文件。
2. 文本要能变成网页，样式统一，不用每篇手动排版。
3. 改完之后，能一键发布到网上。

前端框架当然能做这些，但它会顺带带来一整套东西：依赖、版本、打包、构建命令。我只是想写字，不想每次动笔前先跟环境问题缠斗一番。

## 我用的是哪一套

最后落在 Jekyll 加 GitHub Actions 上：

```text
_posts/*.md  →  GitHub Actions 里的 Jekyll  →  HTML  →  GitHub Pages
```

- **文章**：`_posts/` 里的 Markdown 文件，文件名是 `YYYY-MM-DD-title.md`。
- **构建**：交给 GitHub Actions，跑在云端，不占自己的电脑。
- **发布**：构建结果直接发布到 GitHub Pages 的地址。

也就是说，我的电脑上只需要一个 Git。Node.js、npm、Ruby，一个都不用装。

## 一篇文章长什么样

文章的头部是一小段 Front Matter，告诉 Jekyll 这篇的标题、日期和摘要：

```yaml
---
layout: post
title: 文章标题
date: 2026-10-09
excerpt: 一句话摘要
tags:
  - 标签
---
```

第二个 `---` 下面是正文，用最常见的那套 Markdown 语法就够了：标题、列表、链接、引用、代码块。

写完存盘，推到 GitHub，等一两分钟就能在网页上看到。

## 什么时候它就不够用了

说实话，这套方案不是万能的。如果哪天我需要评论、全文搜索，或者根据数据动态生成页面，静态站点就会开始别扭。

但现在还不用想那么远。
